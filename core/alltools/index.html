    Executables¶

    The core-geth project comes with several wrappers/executables found in the cmd directory, and which, with make all, will be built to ./build/bin/.

    Command Description
    geth Our main Ethereum Classic CLI client, entry point into the networks it supports (see Supported networks). It runs as a full node (default) or an archive node (retaining all historical state). It can be used by other processes as a gateway via JSON RPC endpoints exposed on top of HTTP, WebSocket and/or IPC transports. geth --help and the CLI page for command line options.
    abigen Source code generator to convert Ethereum contract definitions into easy to use, compile-time type-safe Go packages. It operates on plain Ethereum contract ABIs with expanded functionality if the contract bytecode is also available. However, it also accepts Solidity source files, making development much more streamlined. Please see go-ethereum’s Native DApps wiki page for details.
    bootnode Stripped down version of our Ethereum client implementation that only takes part in the network node discovery protocol, but does not run any of the higher level application protocols. It can be used as a lightweight bootstrap node to aid in finding peers in private networks.
    evm Developer utility version of the EVM (Ethereum Virtual Machine) that is capable of running bytecode snippets within a configurable environment and execution mode. Its purpose is to allow isolated, fine-grained debugging of EVM opcodes (e.g. evm --code 60ff60ff --debug).
    rlpdump Developer utility tool to convert binary RLP (Recursive Length Prefix) dumps (data encoding used by the Ethereum protocol both network as well as consensus wise) to user-friendlier hierarchical representation (e.g. rlpdump --hex CE0183FFFFFFC4C304050583616263).
    clef Standalone account and transaction signer, run as a separate process from the node so that key material never sits in the node’s memory. geth talks to it over IPC with --signer. See Clef for the rule engine and setup.
    echainspec Reads, converts and validates chain configurations across the formats this client understands, so a genesis or chainspec file can be checked before a node is pointed at it. Reads from a file or from standard input.
    ethkey Creates, inspects and signs with keyfiles directly, without a running node.
    abidump Decodes a hex-encoded calldata blob against known ABI signatures, for reading a transaction’s input by hand (e.g. abidump <hexdata>).
    devp2p Exercises the peer-to-peer stack directly: discovery lookups, DNS tree publishing, and protocol conformance tests against another node.
    p2psim Drives a simulated peer-to-peer network through the node’s HTTP simulation API, for testing discovery and protocol behavior without real peers.
    era Reads and writes Era1 history files, the archive format for historical chain segments.
    ancient-store-mem Standalone mock server implementing the ancient-store (freezer) interface over IPC, ephemeral and memory-backed. Nothing in this codebase connects to it as a client; it exists for developers exercising the freezer interface in isolation, not as an operator-facing feature.
