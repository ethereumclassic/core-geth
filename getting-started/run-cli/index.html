    Command line

    Running geth¶

    No network flag runs Ethereum Classic

    With no network flag, geth runs Ethereum Classic mainnet, and --mainnet is the same as --classic. Pass --mordor for the test network.

    --ethereum, --sepolia and --holesky are deprecated and refuse to start: this client implements Ethereum upgrades only through Cancun, so it cannot follow Ethereum or its test networks. See supported networks.

    A node on an Ethereum Classic network¶

    For running a node, from an installed geth to a synced, supervised, safely stopped node, see Running a node, which has a guide for each platform.

    1
    $ geth [--classic|--mordor] console

    console starts geth and opens its built-in interactive JavaScript console in one command, through which you can invoke web3 methods (a subset of web3.js) as well as geth’s own management APIs. It is optional: leave it out and attach to an already-running geth instance with geth attach instead.

    To leave the console, type exit or press Ctrl-D, and the node stops with it. Ctrl-C at the console prompt discards the line being typed and leaves the node running. The exception is a terminal that cannot edit the line: one narrower than 12 columns (including one that reports a width of zero), or one with TERM unset or dumb. There, Ctrl-C stops both the line and the node. Started any other way, the node stops as covered in Stop it safely.

    A node on the Mordor test network¶

    For running a node on Mordor, see Run a Mordor node.

    1
    $ geth --mordor console

    console behaves exactly as above; --mordor is what selects Mordor’s own data directory, bootnodes, network ID and genesis instead of Ethereum Classic’s.

    Configuration¶

    Instead of passing every flag on the command line, you can keep your settings in a configuration file. dumpconfig writes out the configuration your current flags produce, which is the easiest way to start one:

    1
2
    $ geth --classic --your-other-flags dumpconfig > /path/to/your_config.toml
$ geth --classic --config /path/to/your_config.toml

    Where a setting comes from more than one place, the command line wins. geth starts from its built-in defaults, applies the --config file over them, and applies command-line flags last. A flag’s environment variable, listed beside it under Command-line Options, counts as the flag: it replaces the file’s value, and the flag given on the command line replaces both.

    A network flag is partly an exception: it sets the chain rules and the network ID, but a file’s BootstrapNodes, EthDiscoveryURLs and SnapDiscoveryURLs replace that network’s own, so a file dumped for one network keeps that network’s peers under another network’s flag.

    Some values in the file are replaced even when no flag names them. On Ethereum Classic and Mordor, and on a private network started with no network flag, geth sets the mining gas ceiling, GasCeil under [Eth.Miner], to 8000000 whatever the file says; pass --miner.gaslimit to use a different ceiling. On every network, Preimages under [Eth], NotifyFull under [Eth.Miner], and DiscoveryV4 and DiscoveryV5 under [Node.P2P] take the values of --cache.preimages, --miner.notify.full, --discovery.v4 and --discovery.v5, defaults included, so set those four on the command line. An archive node records preimages whatever either says.

    Pass --mordor alongside a configuration file dumped with it

    A dumped configuration file does not contain the chain rules. A file dumped with a network flag says so on its first line: # Note: this config doesn't contain the genesis block. The network ID, discovery lists and mining settings are written into the file; which chain’s consensus rules to follow is not.

    With no network flag the node takes Ethereum Classic mainnet’s rules, so a file dumped with --classic needs no flag beside it. A file dumped with --mordor does: started without the flag, the node carries Mordor’s network ID and discovery lists but not Mordor’s chain rules, and it cannot follow Mordor.

    Pass the network flag you dumped with every time you start from that file.

    To reproduce a network’s full chain configuration rather than your runtime settings, use dumpgenesis, which does include the consensus rules:

    1
    $ geth --classic dumpgenesis > classic-genesis.json

    Key derivation on a small machine¶

    Creating an account derives the keyfile’s encryption key with scrypt, and the default parameters deliberately cost a lot of memory. That cost is what makes an offline guessing attack against your passphrase expensive. On a host with little RAM it can be too much: geth account new allocates around 256MB and is killed by the OOM reaper on a small VPS or an embedded node.

    Two flags lower it. They change newly created keyfiles only. An existing keyfile keeps the parameters it was written with, which are recorded inside the file itself.

    Flag scrypt N Memory Roughly
    (default) 218 ~256MB ~1s
    --mediumkdf 216 ~64MB ~250ms
    --lightkdf 212 ~4MB ~100ms 
    1
    $ geth account new --mediumkdf

    Prefer the default, and reach for --mediumkdf before --lightkdf. Each step down divides the work an attacker must do to test a candidate passphrase: --mediumkdf by four, --lightkdf by sixty-four. --lightkdf also lowers p, so it is the weakest of the three by more than the N column alone suggests. The two flags are mutually exclusive and geth refuses both rather than choosing for you.

    None of this is a substitute for a strong passphrase. A weak one is guessable at any of these settings; the parameters decide how expensive each guess is, not how many guesses are needed.
